# P1.2 Network Boundary (design only)

**Date:** 2026-09-14  
**Status:** Design / IPC seam only. **Not** Network Core. No HTTP/TLS/DNS/VPN implementation in this stage.

## Ownership

| Concern | Owner |
|---------|--------|
| Proxy / route **policy** (user settings, profile) | **Browser Process** |
| Applying route to engine networking | **Content Process** (Servo networking) |
| Secrets (proxy passwords, Keychain) | **Browser only** — never on Content IPC as raw secrets |

## Intended flow

```
Browser (settings / NetworkRouter)
   │
   │ BrowserToContent::SetNetworkRoute { mode }
   │   Direct | Proxy{scheme,host,port} | Unavailable{reason}
   ▼
Content Process
   │
   ▼
Servo networking (future apply; currently logged only)
```

## Parameters on the wire (non-secret)

`NetworkRouteMsg`:

- `Direct`
- `Proxy { scheme, host, port }` — **no password field**
- `Unavailable { reason }`

If proxy auth is required later: Browser holds credentials; Content receives a short-lived **capability token** or local auth helper — **not** plaintext password over IPC. Exact mechanism deferred to P2.

## Change / invalid config

| Case | Behavior |
|------|----------|
| Valid Direct/Proxy | Browser sends `SetNetworkRoute`; Content validates strings/sizes |
| Invalid host/port | Fail-closed validation reject |
| VPN / unavailable | `Unavailable` — Content must not silently fall back to Direct |
| Mid-session change | New `SetNetworkRoute` to current Content generation |

## Explicit non-goals (P1.2)

- HTTP stack rewrite  
- TLS rewrite  
- DNS / DoH  
- VPN  
- Full proxy implementation inside Content  

## Gap

`SetNetworkRoute` is accepted and logged in Content; **Servo proxy apply is not wired** — remains a documented gap until P2 Network Core (if chosen).
